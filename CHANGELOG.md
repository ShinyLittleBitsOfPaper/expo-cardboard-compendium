- 2026-11-02, 0.0.2-31: Milestone 3.5 malformed-input tests. `crates/engine/tests/fuzz.rs`: seeded mutation fuzzing (truncations, bit flips, header corruption, splices, garbage; ~25k inputs) over COQD, COQI, price overlay, idmap, COQP patches (cards and prices, damaged patch and damaged base), COQI deltas, the engine (`open`, `attachOverlay`, `applyIndexDelta`, `patchFile` with damaged files) and the C-ABI `call_json` with junk methods/arguments; each must return an error, never panic, hang (>5 s) or exhaust memory, and the unmutated inputs must still work. It found two classes of abort-on-allocation bugs (an abort cannot be caught by `catch_unwind`, so it would have killed the app on a damaged download): (1) counts read from a file sized `Vec::with_capacity` / `HashMap::with_capacity` directly, and zstd sections were decompressed into a buffer of the claimed size; (2) a patch's table row counts drove `push_default` for billions of rows. Fixes: `Reader::remaining()` / `cap(n)` bound every count-sized allocation by the bytes left (coqd, coqi, dict, schema, patch, idmap); new `codec::zstd_exact` streams the decompression, requires the exact claimed length and refuses more than `MAX_RAW` (512 MiB); a patch or index delta whose new-row count exceeds the bytes it carries is corrupt. All workspace tests and `test-data-pipeline.sh` still pass. Set `FUZZ_TRACE=1` to print each mutant (find the one that crashed).
